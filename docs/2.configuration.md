## The `.env` file

The configuration lives in `/var/opt/deploy-party/.env`, written by `install.sh`. To change it:

```bash
nano /var/opt/deploy-party/.env
sh /var/opt/deploy-party/reconfigure.sh   # restarts deploy.party with the new values
```

The file holds secrets (database, Redis, JWT, web push keys). It stays on the server and never goes into a
repository or a ticket.

## Settings worth knowing

| Variable | Values | Meaning |
|---|---|---|
| `NSC__WEBHOOK_TOKEN_MODE` | `off`, `report`, `enforce` | Check of the secret GitLab sends with every webhook (`X-Gitlab-Token`). `enforce` builds only with the right secret and answers 401 otherwise; `report` accepts but logs requests without it. New installations set `enforce` |
| `NSC__REFRESH_BUILD_FILES` | `true`, `false` | Every build writes `Dockerfile` and `docker-compose.yml` from the container settings first, so a changed setting goes live with the next build. A changed file is kept as `….prev`. New installations set `true` |
| `NSC__SWAGGER` | `true`, `false` | Swagger UI and the OpenAPI document of the API. Off by default; deploy.party itself does not need them |

Older installations need a few steps once before they can switch these on, see [Updates](./4.updates.md).
