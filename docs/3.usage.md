## Members

1. Click the plus in the top bar and create a new member.
2. Fill in the form and choose the role.
3. The new member gets an e-mail with a link to set a password.

## Sources

A source is the GitLab or GitHub instance deploy.party builds from.

1. Go to **Sources**.
2. Click the plus in the top bar.
3. Enter a name, for example `GitLab`, and the URL of the instance, for example `https://gitlab.com`.
4. Enter an access token for the API ([GitLab docs](https://docs.gitlab.com/user/project/settings/project_access_tokens/)).

About the token:

- **Use a project or group access token, not a personal one.** deploy.party uses it to clone, to list projects,
  branches and releases, and to create the webhook. It needs the role Maintainer and the scope `api`; add
  `read_registry` and `write_registry` only if you push to the GitLab registry.
- A personal access token reaches every project of its owner. If it leaks, all of them are exposed. A project token
  (`/GROUP/PROJECT/-/settings/access_tokens`) or group token (`/groups/GROUP/-/settings/access_tokens`) is limited to
  what deploy.party deploys.
- Give the token an expiry date and note where it is used.
- The token is passed to `git clone` as a header. It is not stored in the clone, in the image or in the build log.

## Projects

1. Click the plus in the top bar and create a new project.
2. Enter its name.

## Containers

1. Click the plus in the top bar and create a new container.
2. Select the project.
3. Enter the name of the container.
4. Choose the kind:
   - `APPLICATION`: an application built from a source
   - `DATABASE`: a database such as MongoDB or MariaDB
   - `SERVICE`: a ready-made service, for example Directus
   - `CUSTOM`: your own `docker-compose.yml` and `Dockerfile`
5. Select the source and enter the image name.
6. Select the registry.
7. Enter the commands, environment variables and ports.
8. Start the container.

Give every container a health check. Docker Swarm then replaces the old version only once the new one answers, see
[Docker Swarm](./6.server/2.docker-swarm.md).
