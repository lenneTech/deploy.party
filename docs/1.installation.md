## Requirements

- A server with root access (the script installs packages with `apt`, so Debian or Ubuntu)
- DNS: an A record for `YOUR_URL` **and** `*.YOUR_URL` pointing to the server. deploy.party uses `YOUR_URL`,
  `api.YOUR_URL`, `api.terminal.YOUR_URL` and `lb.YOUR_URL` (Traefik), and your containers get their own subdomains

## Install

Log in as root and run the install script:

```bash
ssh root@SERVER_IP
bash -c "$(curl -fsSL https://raw.githubusercontent.com/lenneTech/deploy.party/main/install.sh)"
```

The script asks for everything it needs. It installs Docker, sets up the swarm, writes `/var/opt/deploy-party/.env`
with generated secrets and web push keys, starts Traefik and deploy.party, and on a production setup configures the
firewall (`ufw`): SSH, HTTP and HTTPS open, everything else incoming closed, MongoDB's port explicitly denied.

### With parameters

For automated setups, pass the values directly. Missing values are asked interactively.

```bash
curl -fsSL https://raw.githubusercontent.com/lenneTech/deploy.party/main/install.sh -o install.sh
chmod +x install.sh

# production
./install.sh --name production --url example.com --email admin@example.com --username traefik-admin --password '<password>'

# local, without URL and certificates
./install.sh --local --name dev-server --username admin --password '<password>'
```

| Parameter | Meaning |
|---|---|
| `-l`, `--local` | Run deploy.party locally (no URL, no e-mail) |
| `-n`, `--name NAME` | Instance name |
| `-u`, `--url URL` | Base URL, required for production |
| `-e`, `--email EMAIL` | E-mail for the SSL certificates, required for production |
| `--username USER` | User of the Traefik dashboard |
| `--password PASS` | Password of the Traefik dashboard |
| `-h`, `--help` | Help |

A password given on the command line ends up in the shell history. Leave `--password` out to be asked for it instead.

### Optional: fail2ban

Protect SSH against brute force with fail2ban, for example with
[this guide](https://www.digitalocean.com/community/tutorials/how-to-protect-ssh-with-fail2ban-on-ubuntu-22-04).

## URLs

| Setup | deploy.party | API | Traefik |
|---|---|---|---|
| Production | `https://YOUR_URL` | `https://api.YOUR_URL` | `https://lb.YOUR_URL`, with the user and password from the installation |
| Local | `http://SERVER_IP:3001` | `http://SERVER_IP:3000` | – |

Check that everything runs:

```bash
docker ps
```

## First login

A new installation starts with a default admin account. Sign in with it once, **create your own admin account right
away and delete the default one**. Until then the instance is open to anybody who knows the default login.
