## Look into a container

```bash
docker exec -it CONTAINER_ID bash   # or sh, if the image has no bash
ls -al
cat FILE_NAME
```

## Copy a file to the server

From your machine:

```bash
scp ./FILE_NAME root@SERVER_URL:/tmp
```

## Copy a file into a container

On the server:

```bash
docker cp /tmp/FILE_NAME CONTAINER_ID:/tmp
docker exec -it CONTAINER_ID sh
ls -al /tmp
```

## Import a MongoDB dump

1. Copy the dump to the server and into the database container:
   ```bash
   scp ./DUMP_FILE root@SERVER_URL:/tmp          # on your machine
   docker cp /tmp/DUMP_FILE CONTAINER_ID:/tmp    # on the server
   ```
2. Restore it in the container. For an archive created with `mongodump --archive --gzip`:
   ```bash
   docker exec -it CONTAINER_ID mongorestore --archive=/tmp/DUMP_FILE --gzip
   ```
   For a dump directory, copy the directory and run `mongorestore /tmp/DUMP_DIR`. Add `--drop` to replace existing
   collections instead of adding to them.

Take a backup of the current data before a restore.

## Change data by hand

Example: give a user the role `admin`.

1. Find the database container: `docker ps`
2. Open the MongoDB shell:
   ```bash
   docker exec -it CONTAINER_ID mongosh
   ```
3. Select the database and change the user:
   ```javascript
   use DB_NAME
   db.users.updateOne({ email: 'EMAIL' }, { $addToSet: { roles: 'admin' } })
   db.users.find({ email: 'EMAIL' })
   ```

`$addToSet` adds the role only once, even when the command runs twice. Change data by hand only when the application
offers no way to do it, and note what you changed.
