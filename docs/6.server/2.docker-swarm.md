deploy.party and every container it deploys run in a Docker Swarm.

## Stacks, services, containers

- **Stack**: a group of services, for example `deploy-party` or `traefik`.
- **Service**: runs and scales containers of one kind. If a container crashes, the service starts a new one at once.
- **Container**: one running instance.

## Deployments without downtime

On a deployment Swarm:

1. starts the new container next to the old one,
2. waits until the new one passes its health check,
3. stops the old one only then.

A health check is a command in the container that ends with `0` when the application answers, for example:

```bash
curl --fail http://localhost:3000/meta || exit 1
```

Swarm runs it at the start and then at intervals. A container that fails it for a while is restarted. The results show
up in the logs of the container in deploy.party.

**Without a health check** there is no healthy or unhealthy state: Swarm swaps old and new container at once, and the
application is down until the new one has started. Give every container a health check; NODE containers get one by
default.
